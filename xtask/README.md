# xtask

`cargo xtask gen` turns the SkyrimRE-1.7.104 ledgers into `crates/sre/src/generated/`, `crates/sre/Cargo.toml` (its features follow the groups) and `crates/sre/generated.lock`; it replaces the `generated` folder, so a file no longer generated disappears. The RE repository is found through `SKYRIMRE_DIR` or, by default, as `../SkyrimRE-1.7.104` next to this workspace. The output is committed; `cargo test -p xtask` regenerates in memory with the commit recorded in `generated.lock` and fails if anything on disk differs or the `generated` folder holds a file it does not generate, so the test depends on the input files alone and the recorded commit moves only when `cargo xtask gen` runs (it skips with a message when the RE repository is absent).

## Inputs

Exactly these files are read and hashed into `generated.lock`:

| file | used for |
|---|---|
| `export/symbols.csv` | function and global ids, names, evidence, confidence, decompiler signatures; vtable symbols and slot targets by rva |
| `data/layouts.json` | every RTTI class: fields, size, size kind and evidence, primary base |
| `data/class_structs.json` | the classes without RTTI (`BSTEventSource`, `TESDataHandler`, the event-source holders) and the typed `g_*_ptr` labels |
| `data/rtti.json` | class hierarchy with base displacements, vtables and their slot targets |
| `data/formtypes.json` | the `FormType` values |
| `export/semantic/*.json` | one file per subsystem pass (schema in the RE repo's `export/semantic/README.md`): class and field meanings, typed function and slot signatures with their `nullable` parameters and `retyped` notes, flag sets, global meanings; `nimath.json` holds the math value types |

`export/include/SkyrimRE/Types.h` was the structural reference for what a generated layout should contain; it is not read. The evidence CSVs under `data/evidence/` are already folded into the files above and are not read either.

## Output

The crate reads like one namespace: every class, enum, flag set, free function and global accessor is at the crate root (`sre::TESForm`, `sre::FormType`, `sre::find_form_by_id`), and also in its group module (`sre::forms::TESForm`). The ids and tables the API is built on are under `sre::raw`, hidden from the docs and from completion; `VERSION` is the root's one constant. `src/lib.rs` is hand-written: the resolver, the three call macros and the table types `raw` re-exports.

### Groups

Every class, enum, flag set, free function and global goes to one group module, by this rule:

0. A class that is or derives from `TESCamera` or `TESCameraState` goes to `camera`, whichever pass describes it: the frame pass laid out the camera states and `PlayerCamera`, the render pass `TESCamera`, and a reader looks for all of them next to the map cameras the camera pass describes (16 classes moved, `FurnitureCameraState` among them; their methods now come with the `camera` feature, which `skyrim` enables). A class is described by one pass, so no pass order is involved.
1. A class a semantic pass describes, an enum of a pass, and a free function or global a pass names go to the pass's group (`actors`, `animation`, `audio`, `camera`, `events`, `forms`, `frame`, `graphics`, `input`, `moments`, `nimath`, `papyrus`, `render`, `save`, `ui`, `vmstack`). `FormType` goes with `TESForm`, a flag set with its class.
2. A method, slot, `Deref` impl, base accessor and `singleton()` goes with its class. A global no pass names goes with the class it holds or points to, when it has one.
3. Every other name goes by its outermost namespace when it has one (leading anonymous namespaces skipped), else by the name, to the first of: `script` (`BSScript`, `SkyrimScript`, `SkyrimVM`), `bnet` (`bnet...`), `stl` (`std`), `scaleform` (`Scaleform`, `GFx`, `GAS`), `havok` (`hk...`, `bhk...`), `ni` (`Ni`), `bgs` (`BGS`), `tes` (`TES`), `bs` (`BS`), `combat` (`Combat`), `pathing` (`Movement`, `Pathing`, `Path`), `extra` (`Extra`), `settings` (`Setting`, `GameSetting`, `INISetting`, `INIPrefSetting`), `factory` (`AutoRegister...`, `Concrete...`, any `...Factory` or `...Creator`), else `other`. A prefix counts when an uppercase letter, a digit, `_` or the end follows it (`NiNode` is `ni`, `Night` is not); a global's name is matched without its `g_`.

`groups.rs` holds the rule and `cargo test -p xtask` checks it on examples.

### Files

No generated file is larger than 1,000,000 bytes (286 files, 109 MB): a group's items are packed in order into numbered files when they pass that. `rust-analyzer analysis-stats` on the workspace (rust-analyzer 1.99.0, default features) takes the same before and after the split, 70 s wall and 6.0 GB (53.8 s analysis before, 59.4 s after, within its noise); what changes is that an edit or a go-to-definition touches a 1 MB file instead of one of 19 to 22 MB. Each group is a folder:

- `types.rs` (or `types_1.rs`, `types_2.rs`, ...): the structs with their asserts, the enums and the flag sets. One `#[repr(C)]` struct per class; ledger fields keep their ledger names (`__vftable`, `field_8`, `sinks`); bytes the ledger says nothing about are `unknown_<offset>: [u8; n]`. The last field of every class is `__engine: Engine`, a zero-sized `UnsafeCell` (align 1, so no size or offset changes) that makes the class interior-mutable. A class a semantic pass describes gets a `Meaning:` line, and every field a pass names (in the class itself or inherited from a base at the base's displacement) carries the meaning and its confidence after the ledger source. A class with an exact size (`exact`, and `conflict` where the allocation size holds every field) gets a `size_of` assert; every other class (`lower`, `bounded`, and the three `conflict` classes whose fields pass the allocation size) is padded to its lower bound, says `partial` in its doc and has no size assert. Every ledger field gets an `offset_of!` assert. A class is `#[repr(C, packed)]` when the ledger puts a field below its natural alignment (478 classes); the doc comment says so. `FormType` is `#[repr(u8)]` with `from_u8` and `signature` (a semantic pass may add its meaning and must agree with `formtypes.json`); every other semantic enum is a plain `#[repr(uN)]` enum with `from_uN` (width from the export), renamed `<Name>Enum` when a class has its name (`InputContextEnum`); a math value type (a class of the `nimath` pass: `NiPoint3`, `NiMatrix3`, `NiQuaternion`, `NiTransform`, ...) also derives `Default`; a field the RE side retyped says so after its meaning; a flag set is a `#[repr(transparent)]` struct `<Class>_<field>` with one `SCREAMING_CASE` const per named bit plus `bits` and `contains`.
- `api.rs`: the semantic tier of the callable layer (next section): the `Deref` impls, `impl` blocks of semantic methods, slots, base accessors, field readers and singletons, the pass's free functions, and the global accessors.
- `tier_high.rs`, `tier_medium.rs`, `tier_low.rs`, `untiered.rs`: the functions typed only by a decompiler prototype, by its rating.
- `mod.rs`: the files as private modules, each re-exported into the group when it has items of its own (a file of `impl` blocks only is not), the callable layer behind its features.

`raw` holds what the API is built on:

- `raw::vtables`: one `#[repr(C)]` struct per vtable (`<Class>_vtable`, `<Class>_vtable_<offset>` for secondary tables) with a `slot_N: *const c_void` per slot and the slot target's ledger name, id and confidence in the doc comment; `ID` is the vtable symbol's Address Library id. A slot a semantic pass names gets `SLOT_<name>: usize`; when the pass rates it high and its signature is fully typed, also `pub type <Class>_vtable_<name> = unsafe extern "C" fn(..)` and a `<name>(&self) -> Option<..>` accessor that reads the slot. `ALL` lists every vtable sorted by rva and `find(rva)` looks one up, which identifies a live object's class from its vtable pointer.
- `raw::fns`: `pub const <name>: u64 = <id>` for every function with an Address Library id, a ledger name (not `ID_<n>`) and medium or high confidence, excluding exception-handling funclets. A function a semantic pass describes carries the meaning and the pass's typed signature in the doc, and when the pass rates it high and its signature has a Rust form (see Signatures) it also gets `pub type <name>_fn = unsafe extern "C" fn(..)` over raw pointers.
- `raw::globals`: every global with an id, same shape; the `g_*_ptr` globals say which class they point to, and a global a semantic pass describes carries its meaning, type and accessor id.
- `raw::symbols`: the crash logger's lookup tables. `FUNCTIONS` holds every function `raw::fns` names as a `raw::Function` (rva, id, confidence, name) sorted by rva, `MEANINGS` the semantic pass meanings by rva, `GLOBALS` every global with an id, `HIERARCHY` every RTTI class with its bases; `function_at(rva)`, `meaning_of(rva)` and `global_at(rva)` find the entry at or before an address, since the ledger records no sizes, and `derives(class, base)` walks the hierarchy.
- A table too large for one file is a `raw::Table`, its parts in `<name>_1.rs`, `<name>_2.rs`, ... with `len`, `get`, `iter` and `floor` (the last entry at or before a key); the consts are spread over `part_N.rs` files and re-exported.

The generated root `mod.rs` declares the groups, glob re-exports each (every name is unique across the crate, so nothing is ambiguous), the passes folded in, `raw` and `VERSION`.

## Callable layer

Every engine function a signature can type is a Rust function that resolves its address through the Address Library on the first call and caches it in a static of its own, the way an author calls a member function: `TESDataHandler::singleton()?.get_file(..)`, `form.get_keyword_form()`, `find_form_by_id(0x14)`. The resolver is `versionlib::running`, the process's one database (`<exe dir>\Data\SKSE\Plugins\versionlib-1-7-104-0.bin` with the executable's base), which `hook::Reloc` shares; a missing file or id panics naming both. Each body is one line through three macros of `sre/src/lib.rs`: `address!(id)`, `function!(id, (params) -> ret)` and `virtual_function!(self, index, (params) -> ret)`, which reads the slot from the object's own vtable at every call. The `this` object and every reference argument cross to the engine as raw pointers: the engine writes through them (a constructor into `self`, a setter into its object), which a `&` argument would let the compiler assume it cannot.

- Placement: a function whose first parameter is `this`, or a pointer to the class its name is scoped to, is a `&self` method. Scoped to a laid-out class `S`, it is `S`'s method and gets the subobject it takes as `this`: when the type of `this` names a non-virtual base of `S` (also by its last segment, `IVMObjectBindInterface` for `BSScript::IVMObjectBindInterface`), the base's displacement; when it names `S` or no class, the offset of the one secondary vtable of `S` that holds the function (an override reached through that base: `Actor::ActorValueOwner_GetActorValue` takes `this + 0xB8`, `SkyrimVM::ProcessHitEvent` its sink at +0x88), else the object itself. The method passes `self` moved by that offset (1,928 methods: 27 semantic, 1,117 `tier-high`, 1 `tier-medium`, 771 `tier-low`, 12 `untiered`). When `this` names another laid-out class the function is that class's method; when nothing says which subobject it takes (several secondary vtables, or a type naming no class with no vtable holding the function: `EventSourceHolder_Input::NotifySinks`, 1) it is an `unsafe` associated function with `this` as a parameter. Constness of a template argument (`char_const*`) is kept in the type's name, so such classes resolve. A function scoped to a laid-out class without `this` is an associated function; every other function is a free function of its group. Names are the snake case of the engine name's last segment (the whole name for free functions, `::` as `__`), made unique within one `impl` (free functions: across the crate) across every tier with the most proven tier keeping the plain name; the engine name opens the doc.
- Slots: a slot of a class's primary vtable is a method when a semantic pass names it, or when its target is a ledger-named function of that same class (`Class::Name`, not `vfunc_<n>` or `ID_<n>`) with medium or high name confidence; it is typed by the pass's signature, or by the target's decompiler prototype in that prototype's tier. A derived class whose `Deref` chain already has the method at that slot, under the same name and in a tier at least as proven, does not repeat it. A function reached that way on its own class is not also emitted as a direct call (1,311).
- Inheritance: `impl Deref for <Class>` targets the primary base when the base sits at offset 0 non-virtually, the class holds the base's bytes (the struct is at least as large, or the class is partial: a live object holds every base whatever the ledger knows of its size, and a partial class is never embedded), and every reference to the class is aligned for the base: either the struct is at least as aligned, or no class embeds it by value, so a reference to it is a live engine object at the engine's natural alignment even where the ledger packs the struct. The two layouts are not compared field by field: every field type is plain data, and the ledger often records a base's fields again in the derived class at the widths the derived constructor writes them (`HUDMenu` has a byte at +0x10 where `IMenu` has its movie pointer). 6,366 classes qualify and 123 do not: 122 whose exact size is smaller than their base's (`BGSActionData`, 0x60, under `ActionInput`, 0x70), one for alignment. A non-virtual secondary base at a non-zero displacement gets `as_<base>()` under the same size and alignment conditions, unless the primary base already provides it at that displacement (1,287).
- Fields: a pointer field a semantic pass names with high confidence, on the class the pass describes, gets a reader named after it that returns `Option<&X>` borrowed from the object (`event.actor()`, `refr.loaded_data()`, `actor.current_process()`; 234), so following the engine's own pointers needs no `unsafe`. A derived class reaches it through `Deref`; a callable of the same class with the same name wins and the reader is left out. Scalar and embedded fields are read directly.
- Globals: a class with exactly one `g_*_ptr` label gets `singleton() -> Option<&'static Self>`, a class with several from its `g_<Class>_ptr` label (23). Every other global is a function of its group named after it: a semantic `class:X` global returns `&'static X`, a `ptr:X` global (or another `g_*_ptr` label of a class with several) `Option<&'static X>`, a scalar its address as `*mut T`; a labelled global its address as `*mut X` or `*mut *mut X`; the rest `*mut c_void`.
- Tiers: the semantic passes' functions and slots, the `Deref` impls, base accessors and globals are the semantic tier. Functions typed only by the ledger's decompiler prototype are in the tier named for the prototype's `sig_confidence`: `tier-high`, `tier-medium`, `tier-low`, `untiered`. Each tier is its own file in every group, so a disabled tier is not even parsed. The ledger name filter of `raw::fns` applies, and two kinds of named functions are left out: `vfunc_<n>` names (20,188), which say only that a function sits in a vtable, and CRT static initializers (`crt_init` evidence, 11,634, `void <global>__init(void)`), which run once before `main` and re-initialize their global when called again.

### Features

Structs, enums, flag sets and `raw` are always compiled. The callable layer is not:

- one feature per group (`actors`, ..., `ui`, `bs`, `havok`, `other`, ...): that group's semantic tier, so its methods, `Deref` impls, base accessors, singletons, free functions and global accessors;
- `tier-high`, `tier-medium`, `tier-low`, `untiered`: in every enabled group, the decompiler-typed functions of that rating.

`default` is every group plus `tier-high`, so `sre = { workspace = true }` gives the whole API. A crate that needs less writes `sre = { workspace = true, default-features = false, features = ["forms", "actors"] }`; `framework` and `crash` use no feature, `overlay` the two groups it calls (`events`, `frame`), and `skyrim`, which calls the engine across every subsystem, the 17 groups it builds on (`actors`, `animation`, `audio`, `bs`, `camera`, `events`, `forms`, `frame`, `graphics`, `input`, `other`, `papyrus`, `render`, `save`, `script`, `settings`, `ui`), so a mod on `skyrim` compiles those whatever it names itself. A method reached through `Deref` needs its own class's group: `Actor` methods come with `actors`, the `TESForm` methods an `Actor` derefs to with `forms`. Features never move a type: every struct is always compiled at the same path, so the type names the hook dispatcher compares are the same in a host and a plugin built with other features.

Gating the structs too was measured and left out: following pointer and embedded fields, the structs of `forms` reach 15 of the 29 groups with types, 65 % of the struct source, and every pass group reaches the same set; only `bnet`, `combat`, `extra`, `factory`, `pathing`, `scaleform`, `settings` and `stl` stand alone, together under 20 %. Feature dependencies derived from those edges would save little and tie every group to every other.

The baseline is master `a51a683` (one `v1_7_104` module, files up to 22 MB) measured the same hour; the item 1 numbers (debug 53.6 s with defaults, release 38.5 s) were taken on a busier machine.

|---|---|---|---|---|
| none (`default-features = false`) | 25.4 s | 34.3 s (semantic tier always on) | 22.0 s | |
| `forms` | 25.5 s | | 22.6 s | |
| `forms`, `tier-high` | 25.3 s | | 23.2 s | |

Every method is `#[inline]` and is code-generated only in the plugin that calls it, so the sample plugin's DLL is the same size whatever the features.

### Signatures

Semantic and decompiler prototypes go through one parser. `char` is `c_char`; `uchar`/`ushort`/`uint`/`ulonglong` and `undefined1/2/4/8` are `u8`..`u64`, `int`/`longlong` `i32`/`i64`, `float`/`double` `f32`/`f64`, the few Windows typedefs by width; `undefined` (an unknown result) is the raw `u64`. `bool` is `bool` in a semantic signature and `u8` in a decompiler one. A semantic enum is its `enums` type as a parameter; as a result it crosses as its integer and comes back as `Result<E, uN>`, `Err` holding a value the enum does not name (10 functions and slots return `BSEventNotifyControl` today; the ledger writes most enum results as `int` or `uchar`, which stay integers until a pass names the enum). A pointer or C++ reference to a laid-out class is `*mut X` (`*const X` for a const pointee), to anything else `*mut c_void`; function pointers are `*const c_void`. `/* */` comments are dropped, an array parameter is the pointer C passes (`NiPlane planes[6]` is `*mut NiPlane`), a bare `this` is the object as `*mut c_void`, the Windows handles (`HWND`, `HINSTANCE`, `HMODULE`, `HANDLE`) are `*mut c_void`, `WPARAM` is `usize` and `LPARAM`/`LRESULT` `isize`. A signature with varargs (`...`, `va_list`), a class or unknown type by value, or text that is not a prototype has no Rust form and is left out, counted by reason (`cargo xtask gen` prints them per tier; at 62eead4 the semantic tier leaves out 59: 27 varargs, 14 types the passes do not define by value such as `GFxScaleMode` and `UIMessageResult`, 18 that are prose or carry an adjusted `this+0x58`; the decompiler tiers 120, all unknown types by value but 12 malformed). No signature has a laid-out class by value: the passes write a by-value result in its ABI form with the hidden pointer, after `this` for a member function (`NiTransform* (const NiTransform* lhs, NiTransform* out, const NiTransform* rhs)`, `PlayerCamera::GetFirstPersonDampingOffset(PlayerCamera* this, NiPoint3* out)`) and first for a free one (`NiQuaternion* (NiQuaternion* out, float angle, const NiPoint3* axis)`), which the generator types as pointers. A parameter the pass marks `nullable` is `Option<&X>` in a safe function and stays a raw pointer otherwise; the doc lists the marks and what the RE side retyped. A slot parameter without the mark had no null test in the overrides read, which does not prove the engine never passes null, and its doc says so. The `_fn` and vtable slot types keep enums as integers, since a detour of that type receives whatever the engine passes.

### Safety rule

A function is a safe `fn` only when its signature comes from a semantic pass rated high, it is not a constructor or destructor (`ctor`, `dtor`, `vdtor`, `~X`, `X::X`, and the deleting destructors the passes name `Destroy` or `<Base>_Destroy`), and every parameter other than `this` is a scalar, `bool`, semantic enum, or a pointer to a laid-out class that is const or has RTTI, taken as `&X` (`Option<&X>` when the pass marks it nullable; `&mut X` for a non-const pointer to a math value type, which the engine reads or writes as one value), a class-pointer result comes back as `Option<&'static X>` (valid as long as the engine keeps the object, as in the hand-written layer) and a `char*` result as a raw pointer. Everything else is `unsafe fn` with a `# Safety` section saying why: the pass's lower rating, the raw-pointer parameters by name (a non-const pointer to a class without RTTI, `char*`, `void*`, `BSFixedString*` out-parameters, function pointers), an untyped pointer result, or, for every decompiler-typed function, that nothing checks its prototype. Engine thread requirements a pass states are in its meaning, which opens the doc.

The engine writes its objects behind every pointer it holds, so a `&` to a class must not promise the compiler the memory is unchanged: the `__engine` cell makes every class `!Freeze`, and rustc emits no `readonly` or `noalias` for a reference to such a type. That is today's codegen, not a guarantee: under the language's aliasing model the bytes outside an `UnsafeCell` are still frozen behind `&`, so the `skyrim` layer hands the engine a raw pointer (`&raw mut`) for any object Rust owns that the engine initializes or writes.

Types: `undefined1/2/4/8` become `u8`..`u64`, `float`/`double` `f32`/`f64`, `pointer` `*mut c_void`, `ptr:X` `*mut X`, `class:X` an embedded `X` when `X` has an exact size equal to the field width (else `[u8; n]`), `vtbl:X:off` `*const raw::vtables::X_vtable[_off]`, anything else `[u8; n]`.

Identifiers: `::` becomes `__`, any other run of non-identifier characters `_`, a leading digit gets `_`, Rust keywords get a trailing `_`, names over 120 characters are cut to 96 plus a hash of the original, and duplicates within one namespace get `_2`, `_3`, ... in sorted order. Output order is by original name everywhere, so a regeneration from unchanged inputs produces no diff.

## Not generated

Functions the ledger has not named (`ID_<n>` placeholders) and low-confidence names (`_caller`, string names, `NoRTTI_`) are left out of `raw::fns` and the callable layer, unless a semantic pass names them; a mod reaches them by raw id through `hook::Reloc`.
